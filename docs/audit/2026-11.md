# Code audit, November 2026

An audit of zack.land for security, speed, technical SEO, accessibility, unused code and readability. It lists findings only. Nothing in the site was changed; each fix ships later as its own small pull request that links back to its finding here.

- **Code audited:** `master` at `5abfb6a` (2026-11-09). The live site served the same build.
- **Method:** seven reviewers read the code in parallel, one per area (readability was split in two: the 3D scene, and everything else). The claims that drive the ranking were then re-checked by hand against the code and the live site.
- **Size of the code:** about 14,500 lines of application source and styles, the head build scripts beside them, 7,000 lines of unit tests in 61 files and 2,200 lines of Playwright specs.

Corrections to the findings:

- **B1:** "an unused import under a rule set to `error` is already on `master`" is wrong. ESLint reported 0 errors on `master`; the unused import was one ESLint does not flag. The gate was broken all the same: on a file with an error, the old script exited 0.
- **S4:** the plan was report-only first. It shipped enforced instead. Report-only with no reporting address does nothing in Safari, and WebKit's console line about it failed Playwright's `addStyleTag` (six moving-views cases on #169). The policy was walked first on the live site with it applied, in Chrome and WebKit, with zero violations, and again on the live site after #172 merged.
- **S8:** two of the six `http://` links are still `http://`. They name a host the public-repository push guard will not let an agent commit; the owner can change them.
- **P1:** the files are found late, but the fix proposed is wrong and is not shipped. Starting the scene's files before the scripts have run made no page faster and some slower, since the link is the bottleneck and the 4.3 MB took bandwidth from the scripts the scene needs first. Median seconds to the dark screen lifting, 390 by 844, uncached: home over HTTP/2 through a 9 Mbps link, 5.3 on `master` and 5.6 with it; the same with the processor 4 times slower, 7.2 and 7.8; `/contact` on DevTools slow 4G, 9.4 and 15.1. And `<link rel="preload" as="fetch">` would have downloaded the scene twice on Safari: WebKit never hands a preloaded file to `fetch()`. The smaller files of P2 and P5 are the fixes that reach the scene's download.
- **P3:** the owner chose to keep the intro as it is, on every first load and every page.
- **Not found by the audit:** every QA walk on this repository hung after the catalog pin moved to `ec2b505954`. The QA note in `.github/workflows/qae-explore.yml` tells the explorer to stub `requestAnimationFrame`, and the catalog's new width capture waited on animation frames with no limit. Greenbauer/vibe-verifier#332 bounds that wait; #173 moved the pin past it. The note stays.
- **Open since:** the first two tests of one end-to-end shard time out on a cold CI runner about one run in four, because the first page load stalls the main thread in software rendering (the 6-second cap never fires). Its fix is #174.

Still open from the original findings: S2 (rate limit, waits on the owner's choice), the pre-commit hook (B1: it is still not executable, owner's choice), speed, SEO, accessibility, the rest of the unused code and packages, and readability.

## Summary

The code is in better shape than its size suggests. Tests pass (474 of 474), the build is clean, SEO scores 100 on every route, mail injection is handled, the workflows are pinned and scoped, and almost nothing is plain dead code. The gains are concentrated in a few places:

1. **Privacy.** Eight photos and one video in `public/` carry GPS coordinates. All nine are reachable by address, and five are shown on pages.
2. **First load.** Every page waits under a dark screen for 4.3 MB of 3D files that the browser only learns about after the scripts have run. On a slow phone connection the 6 second cap fires first and the page opens without the head.
3. **Lint does not gate.** `npm run lint` runs ESLint in the background, so its failures never block a commit, and no workflow runs it.
4. **Keyboard and screen reader use on a phone-width window.** The menu button is a plain `div`, and form labels are not tied to their fields.
5. **Less code.** About 1,100 lines, 7 packages now (and Cypress after two specs are ported), and 20.6 MB of unreferenced files can go with low risk.

## How to read the findings

Each finding has an ID, the evidence, whether a visitor would see the fix, the risk that the fix breaks something, and a size: **S** is under 50 changed lines, **M** is a focused change in a few files, **L** is a restructure. Findings marked *suspected* were read in the code but not observed in a browser. Sections are in the order fixes should ship. The pull-request table near the end moves a few items earlier where they belong with another fix, and one on purpose: the lint gate (B1) is tooling that every later change relies on, so it ships right after the security fixes.

**Fixes**

- **S1:** delete the seven unreferenced `IMG_*` files (see D1) and re-save the five used photos without metadata. The tags stay in public git history; removing them there needs a history rewrite and a forced push, which is the owner's decision.
- **S2:** see [Decisions](#decisions-for-the-owner). The option with no new service is a rate-limit rule on `/api/email` in Vercel's firewall, set in the dashboard. Whether this plan includes it was not confirmed.
- **S3:** add `headers()` in `next.config.js` with `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin` and a `Permissions-Policy` that turns off camera, microphone, geolocation, payment and USB, plus `poweredByHeader: false`. Use `SAMEORIGIN`, not `DENY`: the QA explorer frames the site from its own origin. Do not list autoplay or fullscreen: the YouTube embed needs them.
- **S4:** ship the policy below as `Content-Security-Policy-Report-Only` first, walk a preview (all four pages, play a YouTube post, submit the form), then enforce. It keeps `'unsafe-inline'` for scripts because every page is static and nonces would force each page to render per request. Its value is in what it limits: framing, `base-uri`, plugins and where a compromised package could load from or send to. The two Google hosts marked * come from memory of Google's guidance and must be confirmed on the preview.

  ```
  default-src 'self';
  script-src 'self' 'unsafe-inline' https://www.google.com/recaptcha/ https://www.gstatic.com/recaptcha/ * https://www.youtube.com;
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:;
  font-src 'self';
  media-src 'self';
  connect-src 'self' https://www.google.com/recaptcha/;
  worker-src 'self' blob:;
  frame-src https://www.youtube.com https://www.google.com/recaptcha/ https://recaptcha.google.com/recaptcha/ *;
  object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'self'
  ```

- **S5:** when the secret is unset and `VERCEL_ENV` is `production`, refuse the submission. Keep the skip everywhere else so local runs and the QA container still work.
- **S6:** delete the branch, keep the log line.
- **S7:** `requireTLS` in production only. The QA mail sink speaks plain SMTP.
- **S9:** move `myHead.obj` beside the build scripts and update `scripts/build-head.mjs:47`; delete the PSD; move the brand notes to `docs/`.
- **S11:** remove the variable in Vercel and revoke the key at Behance.

**Fixes**

- **P1:** in `app/(root)/layout.tsx`, call `preload(url, { as: 'fetch', crossOrigin: 'anonymous' })` from `react-dom` for the three files. This is the best first speed fix: a few lines, no visible change, and it moves 4.3 MB of downloads to start alongside the script.
- **P2:** have the build script write the page's file with only the shown expressions. See [Decisions](#decisions-for-the-owner): it depends on whether the other 12 are planned.

- **P4:** for videos, drop `autoPlay`, add `preload="none"` and a poster, and play or pause on the `paused` prop. Keep image `preload` on the first post only.
- **P5:** a build script writes the bytes and a small loader builds the same texture. Prove it with a test that compares the new bytes with the old loader's output.
- **P6:** import the scene files through the bundler so they get hashed names and the one-year cache. Whether the bundler emits these file types that way must be confirmed with a build.
- **P9, P12, P13:** measure first with a throttled trace on a real phone. Fix only what the trace shows.

Not worth doing: splitting three.js out with a dynamic import. While the dark screen waits for the scene, it buys nothing a visitor can see.

The 404 page's video (2.0 MB) loads only there.

### Load timings

Measured on the live site in headless Chrome with the GPU on, at a phone-sized window (390 by 844), with nothing cached. One run per row, on a fast Mac, so a real phone's processor would add to every number.

| Connection | Route | First paint (the dark screen) | Dark screen starts to lift | Page content let in |
|---|---|---|---|---|
| Not throttled | `/` | 0.4 s | 2.2 s | 4.5 s |
| Not throttled | `/contact` | 0.4 s | 1.7 s | 7.0 s |
| Fast 4G (9 Mbps, 60 ms) | `/` | 0.5 s | 5.5 s | 7.9 s |
| Fast 4G | `/contact` | 1.0 s | 5.9 s | 11.2 s |

| Slow 4G | `/contact` | 3.6 s | 9.5 s | 9.5 s |

What the rows show:

- **The wait is the download.** On fast 4G the dark screen holds for 5.5 s against 2.2 s unthrottled. P1, P2 and P5 attack this directly.
- **The intro adds 2.3 s on the home page and 5.3 s on `/contact`** after the scene is ready (P3). On fast 4G a visitor who followed a link to the contact form waits 11 seconds to see it.
- **On slow 4G the 6 second cap fires.** The scripts take about 3.4 s to arrive, the cap runs out 6 s later, and the page opens without the head.
